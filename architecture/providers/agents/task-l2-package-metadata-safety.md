# L2 — Arbitrary-Folder Package and Metadata Safety

## Objective and dependency

Implement [the accepted local fidelity boundary](../local/01-package-and-metadata-safety.md) before the app can point the provider at arbitrary user folders. Begin only after the user confirms L1 merged and the orchestrator verifies the merged default-branch SHA. This is a high-risk standalone PR.

## Exact scope

- Add typed positive scan exclusions to the core snapshot/domain surface and carry them through reconciliation, planning, preview, activity, and recovery without treating them as absence.
- Add the local package-ancestry validator that accepts an already canonical selected root under caller-held live access, walks that root through ancestors only to its volume root, rejects a package root or any selection inside a package, and fails closed on unreadable ancestor package metadata. L4 enrollment will invoke it while holding the scope. Make `LocalFolderStorageProvider` detect encountered package subtrees with `isPackageKey`; unsupported xattrs, Finder tags/FinderInfo, and nonempty resource forks; non-baseline permissions/special bits; ACLs; and non-baseline ownership.
- Derive filesystem kind from `lstat`: support only regular files at exactly `0644` and directories at exactly `0755`, owned by the effective user and primary group; retain settings exclusion for symlinks; emit typed item exclusions for every known special kind; and make indeterminate kind evidence incomplete/ambiguous. Create and verify targets at those baselines; exclude every other profile before observation, hashing, fetching, or mutation.
- After ordinary observation and move matching, make every tracked record still missing at a location with one or more opaque subtree exclusions a visible, exact-evidence, non-approvable relocation-ambiguity hold. It blocks deletion/mutation, approval, base/recovery convergence, and success language regardless of root history or apparent path relationship. Ordinary deletion remains available only when the same missing location snapshot has no opaque subtree exclusion.
- Add one all-location live-access classification preflight after confirmation and before the schedule's first mutation. Prevent descent into excluded directories and retain mutation-adjacent and recovery checks as defense in depth.
- Add core/local tests only in test-created temporary directories. Do not add bridge/app persistence or folder-picker work.

Do not implement metadata copying, package transfer, confirmation overrides, OAuth/cloud/NAS qualification, FSEvents, or background work. This user-authorized correction revises only L2's special-kind and opaque-relocation boundaries; any further material policy change still requires a separately authorized architecture revisit.

## Acceptance and focused tests

L2 solely owns [LW-15 and LW-16](local-workspace-mvp.md#acceptance-matrix--one-owner-per-scenario). Named focused tests MUST cover package-root rejection; selecting a directory inside a package; unreadable ancestor package metadata; bounded ancestor walking that stops at the volume root; package-subtree no descent; ordinary baseline files/directories accepted and created with exact `0644`/`0755` modes; every metadata reason; non-baseline file/directory modes; ordinary `0664`/`0775`, executable, `0600`, private, and foreign-owned fixtures; ACLs; non-baseline user/group ownership; all represented special filesystem kinds; real FIFO and Unix-socket scan/classification where portable on macOS; directory-subtree blocking; kind/probe ambiguity making the scan incomplete/refused; and a previously tracked directory with tracked descendants becoming subtree-excluded. That subtree regression MUST use component-aware normalized/case-folded `SyncPath` ancestry and prove every covered descendant waits at every location with zero absence/deletion decisions, provider mutations, base updates, convergence, or success language.

Opaque-relocation regressions MUST prove: stable long-standing roots plus external relocation; long-standing unrelated roots plus genuine deletion as the accepted visible hold limitation; no opaque roots plus the ordinary inspectable delete-to-trash path; multiple roots; addition, removal, and reappearance; case/Unicode-equivalent respelling with exact raw root evidence; per-location isolation; legacy/no-op/in-sync base state; incomplete scans; tracked descendants; move-matching before the hold; deterministic reruns; rejected generic approval; and unchanged base/recovery state. Evidence MUST name only the exact snapshot roots and never fabricate descendants.

Add a realistic exclusion-volume qualification over disposable representative Documents/Projects trees. It MUST prove complete-scan accounting, bounded preparation, one durable exact path/scope/reason per exclusion root, individually inspectable evidence, stable display-only grouping, and no synthetic per-descendant rows. Record measurements. If intended roots become impractical or evidence cannot meet the performance/UI budget, stop and trigger the separate architecture revisit named in the normative policy; do not silently widen permissions or ownership support in L2.

The proving preflight regression MUST prepare and confirm a multi-location schedule, make the **last participating location** acquire an exclusion before execution, and assert through every provider call log and filesystem that the all-location preflight aborts before the first mutation everywhere. Equivalent ambiguity/unavailability variants MUST also prove zero mutations and fresh-prepare requirement.

Run the provider conformance and local-provider suites, then the full Swift suite. Static audits MUST show package/metadata reasons are typed, no permanent-delete path was introduced, no exclusion is filtered before planning, and no subtree coverage uses raw string prefixing. The exact frozen/pushed head requires automated macOS validation when available and user-Mac tests using disposable folders containing a package root, a selection inside a package, tag/xattr/FinderInfo fixture, resource fork, and representative permission/ownership volume.

## Finish and stop

Apply the shared [validation ladder](local-workspace-mvp.md#validation-ladder-for-l2l5). The durable orchestrator's [LW-20](local-workspace-mvp.md#acceptance-matrix--one-owner-per-scenario) evidence gate blocks L2. Finish only when LW-15/LW-16 pass, full validation is green, no P0/P1 remains, and P2 risks have triggers. Freeze, record the cutoff/evidence, stop for exact-SHA user validation, then stop for the user merge. Do not start L3.
