# L2 — Arbitrary-Folder Package and Metadata Safety

## Objective and dependency

Implement [the accepted local fidelity boundary](../local/01-package-and-metadata-safety.md) before the app can point the provider at arbitrary user folders. Begin only after the user confirms L1 merged and the orchestrator verifies the merged default-branch SHA. This is a high-risk standalone PR.

## Exact scope

- Add typed positive scan exclusions to the core snapshot/domain surface and carry them through reconciliation, planning, preview, activity, and recovery without treating them as absence.
- Add the local package-ancestry validator that accepts an already canonical selected root under caller-held live access, walks that root through ancestors only to its volume root, rejects a package root or any selection inside a package, and fails closed on unreadable ancestor package metadata. L4 enrollment will invoke it while holding the scope. Make `LocalFolderStorageProvider` detect encountered package subtrees with `isPackageKey`; unsupported xattrs, Finder tags/FinderInfo, and nonempty resource forks; non-baseline permissions/special bits; ACLs; and non-baseline ownership. Preserve unsupported-xattr exclusion as the default. Add a typed adapter for exact, case-sensitive raw `com.apple.provenance`: native predicate `0` maps to ignored, every native nonzero maps to preserve, and typed binding-unavailable/call-failed outcomes fail closed. Injected ambiguity is a test-seam outcome, not a native return.
- Make source-to-stage fetch, stage-cache materialization, store/replacement, cross-location or cross-filesystem relocate fallback, and recovery rematerialization data-fork-only. Never explicitly set, copy, or delete provenance or request metadata-copy behavior for it. Preserve same-object same-filesystem move semantics without treating attached OS metadata as synchronized truth, and leave new/replaced destination provenance outcomes to the OS without copying old destination payloads onto new content.
- Support only regular files at exactly `0644` and directories at exactly `0755`, owned by the effective user and primary group. Create and verify targets at those baselines; exclude every other profile.
- Add one all-location live-access classification preflight after confirmation and before the schedule's first mutation. Prevent descent into excluded directories and retain mutation-adjacent and recovery checks as defense in depth.
- Add core/local tests only in test-created temporary directories. Do not add bridge/app persistence or folder-picker work.

Do not implement metadata copying, package transfer, confirmation overrides, OAuth/cloud/NAS qualification, FSEvents, or background work. If the accepted policy cannot be implemented without weakening it, stop and route a new standalone architecture PR; do not edit normative architecture in L2.

## Acceptance and focused tests

L2 solely owns [LW-15 and LW-16](local-workspace-mvp.md#acceptance-matrix--one-owner-per-scenario). Named focused tests MUST cover package-root rejection; selecting a directory inside a package; unreadable ancestor package metadata; bounded ancestor walking that stops at the volume root; package-subtree no descent; ordinary baseline files/directories accepted and created with exact `0644`/`0755` modes; every metadata reason; non-baseline file/directory modes; ordinary `0664`/`0775`, executable, `0600`, private, and foreign-owned fixtures; ACLs; non-baseline user/group ownership; directory-subtree blocking; probe ambiguity making the scan incomplete/refused; and a previously tracked directory with tracked descendants becoming subtree-excluded. That subtree regression MUST use component-aware normalized/case-folded `SyncPath` ancestry and prove every covered descendant waits at every location with zero absence/deletion decisions, provider mutations, base updates, convergence, or success language.

The provenance classifier MUST have injected/pure tests proving: native exact `0` maps to ignored; every native nonzero maps to preserve; typed adapter unavailability/call failure and injected test-seam ambiguity are excluded/refused; every case, prefix, suffix, or canonicalization near-match is excluded; and exact provenance plus any other xattr is excluded. File and directory fixtures carrying only exact non-preservable provenance MUST yield ordinary observations, the directory's descendants MUST be scanned, and no synthetic exclusion may appear. Destination-created/rescan cases and appearance, disappearance, and value-change cases MUST remain stable when synchronized truth is otherwise unchanged. Tests MUST prove scan, all-location preflight, mutation-adjacent checks, and recovery use the same rule, and that a classification flip to preserve or a fail-closed adapter outcome stops before mutation, base update, or recovery convergence. No test or production evidence may expose raw payload bytes.

Transport regressions MUST cover create, edit/overwrite, cross-location materialization, same-object same-filesystem relocate, copy-fallback relocate, interruption/recovery, and overwrite/rescan. Injected call/flag evidence MUST prove every staging and materialization path selects data-fork-only behavior, source provenance is never propagated as copied metadata, and no Aetherloom path explicitly sets or deletes provenance. Tests MUST accept OS-owned destination provenance being retained, regenerated, changed, or omitted without affecting convergence, and MUST NOT compare, log, expose, or use opaque payload bytes. A same-object move may retain attached OS metadata; copy fallbacks may not propagate it.

Add a realistic exclusion-volume qualification over disposable representative Documents/Projects trees. It MUST prove complete-scan accounting, bounded preparation, one durable exact path/scope/reason per exclusion root, individually inspectable evidence, stable display-only grouping, and no synthetic per-descendant rows. Record measurements. The exact-head real-macOS probe MUST reuse the preserved Documents/Projects fixture from the failed PR #27 run (`/tmp/aetherloom-pr27-fixture.0U9g39`; prior log `/tmp/aetherloom-pr27-real-metadata.log`), prove more than zero ordinary observations, and show exclusions only for intentionally unsupported fixture roots. Capture OS and toolchain, the live predicate result, exact per-root observation/exclusion counts, exclusion paths and reasons, and timing; preserve the fixture and log on failure. If intended roots remain impractical or evidence cannot meet the performance/UI budget, stop and trigger the separate architecture revisit named in the normative policy; do not silently widen permissions or ownership support in L2.

The proving preflight regression MUST prepare and confirm a multi-location schedule, make the **last participating location** acquire an exclusion before execution, and assert through every provider call log and filesystem that the all-location preflight aborts before the first mutation everywhere. Equivalent ambiguity/unavailability variants MUST also prove zero mutations and fresh-prepare requirement.

Run the provider conformance and local-provider suites, then the full Swift suite. Static audits MUST show package/metadata reasons are typed, only the exact raw provenance name can reach the live adapter, native returns are interpreted only as zero/nonzero, opaque provenance values never enter logs/fingerprints/authority, every transfer/rematerialization path is data-fork-only with no metadata-copy option, no provenance set/delete path exists, no permanent-delete path was introduced, no exclusion is filtered before planning, and no subtree coverage uses raw string prefixing. The exact frozen/pushed head requires automated macOS validation when available, the app build, and user-Mac tests using disposable folders containing a package root, a selection inside a package, provenance ignore/preserve/adapter-failure cases, data-fork-only transfer cases, tag/xattr/FinderInfo fixture, resource fork, and representative permission/ownership volume.

## Finish and stop

Apply the shared [validation ladder](local-workspace-mvp.md#validation-ladder-for-l2l5). The durable orchestrator's [LW-20](local-workspace-mvp.md#acceptance-matrix--one-owner-per-scenario) evidence gate blocks L2. Finish only when LW-15/LW-16 pass, full validation is green, no P0/P1 remains, and P2 risks have triggers. Freeze, record the cutoff/evidence, stop for exact-SHA user validation, then stop for the user merge. Do not start L3.
